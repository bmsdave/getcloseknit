# User Feedback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 👍/👎 votes on area-page cards and the Find my area shortlist, an anonymous 1–5-star feedback form with rating-dependent reason chips and free text, a gentle prompt after the first action, and a Grafana "Feedback" dashboard.

**Architecture:** One production-only Postgres table `site_feedback` (upsert by a browser-made `client_id`), written by a new FastAPI module `area_api/site_feedback.py` behind `POST /api/v1/feedback`, proxied by a Next route. Browser side: `lib/feedback.ts` (send + local memory), `QuickVote`, `FeedbackForm`, `FeedbackPrompt`. Grafana reads the table through the existing read-only `close_knit_analytics` role.

**Tech Stack:** Python 3 / FastAPI / psycopg (unittest), Next.js + React (node:test via `tsx --test web/tests/*.test.ts`, Playwright `web/e2e`), Grafana JSON generated by `deploy/tools/grafana_dashboards.py`.

**Spec:** `docs/superpowers/specs/2026-10-14-user-feedback-design.md` (committed 8295a20). On approval, copy this plan to `docs/superpowers/plans/2026-10-14-user-feedback.md` and commit it.

**Execution (recommended): Native** — I implement the 10 tasks in this session, then one fresh reviewer on the most capable model checks the whole branch. The tasks build on each other in a straight chain of small interfaces defined above, so per-task reviews add cost (your token-efficiency rule) without much extra safety. The alternative is Subagent-driven: a fresh implementer and reviewer per task.

## Global Constraints

- Anonymous: no visitor id, session id, email field, IP or user agent stored. Messages pass `feedback.scrub()` (`api/area_api/feedback.py`).
- Feedback is stored even with "Analytics off", GPC or DNT; it never goes through `product_event`.
- Retention 365 days; purge on each insert and via CLI `purge`.
- Message ≤ 2000 chars (form), ≤ 500 (vote follow-up input, client `maxLength`); server rejects > 2000.
- Surfaces/targets/tags exactly as the spec's allowlist table:
  - `area_card` targets `price sales living schools around environment planning council home`; tags `hard_to_understand looks_wrong missing_info out_of_date`.
  - `shortlist` targets `buy rent`; tags `too_expensive too_far wrong_areas too_few unclear_why`.
  - `site` (review, no target); low tags `hard_to_use missing_data wrong_data not_covered slow broken`; high tags `easy_to_use useful_data found_areas looks_good fast`.
- Copy (exact): "Was this useful?", "Are these areas a good fit?", "How's Close Knit so far?", stars *Terrible, Poor, OK, Good, Great*, "What worked well?", "What got in the way?", placeholders "What would make it better?" / "What did you like most?", "Anything else?", "Thanks", "Thanks — this helps", "Thank you!", "Please don't include names or contact details. We can't reply — this form is anonymous."
- Chip labels: area card *Hard to understand · Looks wrong · Missing what I need · Out of date*; shortlist *Too expensive · Too far from my places · Areas I wouldn't consider · Too few results · Not sure why these*; high *Easy to use · Useful data · Found good areas · Looks good · Fast*; low *Hard to use · Missing data · Wrong data · My area isn't covered · Slow · Something broke*.
- Touch targets ≥ 44px; existing CSS tokens only (light + dark); no new colours.
- Prompt: after first `portal_click` / `watch_open` / `brief_share` in a page session; dismiss → 30 days, sent review → 90 days; never on first page view, never while another dialog is open, once per page session.
- localStorage keys: `close-knit.votes.v1` (cap 200 entries), `close-knit.feedback-prompt.v1`. Every storage access in try/catch.

## Review Focus

1. **Storage blocked** (Safari private, quota): a vote still POSTs and the widget renders; the prompt simply never shows. → test in Task 4.
2. **Changing a vote / adding reasons** reuses the same `client_id`; an update can't change `kind`/`surface`/`target`/`area`. → tests in Tasks 2 and 4.
3. **Whitespace-only or contact-laden text**: trimmed to NULL; emails/phones replaced. > 2000 → 422. → Task 2.
4. **API down or demo mode**: form shows an inline error and keeps the typed text; vote failure is silent. → Task 6 e2e.
5. **New shortlist after a vote**: the widget resets for the new ranking (key includes the ranking hash); old vote is kept for the old ranking. → Task 4 unit + Task 5 e2e.

export type FeedbackSurface = "area_card" | "shortlist" | "site";
export interface FeedbackPayload { client_id: string; kind: "vote" | "review"; surface: FeedbackSurface;

export function promptDue(store: Storage | null, now: number): boolean;
export function postponePrompt(store: Storage | null, now: number, days: 30 | 90): void;
