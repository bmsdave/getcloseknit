# Rankings: approved catalogue and build plan

Approved by the user on 2026-10-11. Source: rankings-design workflow (design + critique). The critique's
changes are binding (section 'Critique'). User decisions: 'Most places for families' (playgrounds, nurseries,
libraries per km²) instead of a composite family score, with a clear on-page explanation of how the figure is
made. Never rank areas by ethnicity, religion, age or other protected characteristics; neutral place wording;
area prices only, never a per-home value (PR #28 wording tests). Dropped: fewest-late-night-venues, largest-primary-schools, largest-secondary-schools, most-social-rented-homes.

## Architecture

Extend `RankingDefinition` (web/src/lib/area-pages.ts) so each entry has a `group` field and a `kind` that tells the three sources apart:
- **metric**: today's path, unchanged.
- **lens**: a custom-preset id plus a carrier.
- **school**: an axis plus a phase.

The index page groups entries by `group`. The `[slug]` page branches on `kind`.

**Lens rankings.** Computing them per request would cost 10 rate units each and could push entries out of the 64-entry LRU, so they are precomputed at release time instead. A new step runs `evaluate()` once per preset across all LSOAs. It then rolls the results up the `area_geography` parent chain:
- count: sum, divided by land area, so the figure is per km²
- variety: set union
- nearest: median of the LSOA walk minutes

The output is stored per release and served at `/api/v1/area-values/lens/{preset}?carrier=msoa|borough`, which has the same shape as the crime packs. `loadAreaPages` merges these packs into `buildIndex` as pseudo-metrics `lens:{preset}`, so `buildRanking`, ties and `RANKING_LIMIT` work as they do now. These pages cite OSM (ODbL).

**School rankings.** A new endpoint, `/api/v1/school-rankings/{axis}?phase=&limit=100` in `schools.py`, reads `school.attributes`. It applies cohort ≥ 30, drops suppressed rows, and never mixes report-card grades with legacy grades. Each row returns urn, name, borough, value, cohort and year. A new `SchoolRankingList` renderer shows the OGL attribution and the caveats for provisional and last-year figures.

All rankings stay runtime-rendered with `connection()` and the 1-hour cache. Only the slug list is fixed at build time. The e2e heading count should be derived from `RANKINGS.length`.

## Rejected

- A composite 'most family-friendly' or 'best area for families' score: this is a judgement, it mixes crime, schools and income in a way that implies who lives there, and it breaks the neutral-name rule. Replaced by most-places-for-families (a count of places).
- Any ranking by ethnicity, religion, diversity, age profile, or by counts of places of worship: protected characteristics, and about people, not places.
- Joke and brand pairs (kebab-cafe, good-coffee-kebab, pret-greggs, bakeries-betting, indie-cafes share): fine on the Explore pages, but not suited to SEO league tables, and they name brands.
- 'Cheapest areas', 'best value' and 'most affordable': judgement wording. The price rankings stay neutral (lowest typical price) and area-level only, with no per-home valuation.
- A single Ofsted 'school score' that combines report-card and legacy grades: forbidden (etl_schools.py:290).
- Admissions rankings ('easiest to get into', distance cutoffs, oversubscription): admissions are not loaded and schools.py returns 'unavailable'.
- Sixth-form or A-level, single-sex, capacity and independent-school rankings: none of this data is ingested.
- Schools outside London: the ETL is London-only.
- 'Safest areas': overclaims. Recorded crime per 1,000 stays the framing, and borough-lowest-crime duplicates borough-crime, which already lists every borough.
- 'Least social-rented homes': reads as an exclusionary filter. Only the descriptive housing-mix ranking is kept.
- Evaluating lenses per request: 10 rate units per call, and it could push entries out of the 64-entry LRU. Precompute at release time instead.
- Raw lens counts per MSOA without normalisation: MSOAs differ in land area, which skews the result. Use density (per km²), except for variety and nearest.

## Critique

Changes needed:

**1. Data checks**
- `highest-food-hygiene`: the metric is "% of food places rated 4–5" (`map-legend.ts:27,78`), not an average rating. Set the column to "Food places rated 4–5" with `desc`.
- `closest-to-a-station`: `asc` is correct, because the value is walk minutes (`map-legend.ts:26`).
- `most-expensive` / `least-expensive`: the column says "Typical price" but the source is £/m². Rename it to "Typical price per m²".
- Lens packs are already rolled up to each carrier. `rankingValue` must read the carrier value directly, not the median of descendants.
- `most-universities`: the column is a raw "Campuses" count, which breaks the density rule. Use per km².
- `top-secondary-progress-8`: apply the 2023/24 cohort. The cohortSize field is 2024/25.

**2. Wording**
- Drop `most-social-rented-homes`. It works as a proxy for who lives there.
- Exclude City of London from borough density rankings, or add a footnote. Its tiny area will top every list.
- Set a minimum place count on MSOA density so a few venues in a small area can't top a list.

**3. Missing rankings (data exists)**
- `typical-price-terraced`, `-semi`, `-detached` (`contracts.ts:16-18`): add highest/lowest for each, or one page with a type switcher.
- Quietest areas, from the `noise` factor `any55Share`. Frame it as the lowest share exposed to 55 dB+.
- Shortest commute (`commute`), most energy-efficient homes (`epc-share`), lowest leasehold share.
- Nearest park, GP and supermarket. These place types are in `contracts.ts:275`.

**4. Duplicates**
- `fewest-late-night-venues` mostly mirrors `most-nightlife`. Drop it.
- `largest-primary-schools` / `largest-secondary-schools` are low value. Defer them.
- `outstanding-primary-schools`: drop the borough pagination and use the same filtered-list renderer as the secondary list.

**5. Tasks**
- Move task 4 (discriminated union) up to second place. Tasks 7 and 9 depend on it.
- Split task 3 into one commit per metric.
- Tasks 6 and 9 need the API (tasks 5 and 8) deployed first. Each new kind needs a "hide page and leave it out of the sitemap when the pack or endpoint is empty" guard, so the web commits can ship on their own.
- Add a task for the noise, commute, EPC and house-type rankings after task 3.
